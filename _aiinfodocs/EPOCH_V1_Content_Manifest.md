# EPOCH V1 Content Manifest

Status: **V1 prototype content lock**  
Schema: `1.0.0` · Content: `1.0.1-v1` · Compatible rules: `1.2.0-v1-final`

## 1. Purpose and authority

This is the smallest coherent authored pool for complete 24-turn prototype matches, deterministic simulation, Growth-versus-Insight choices, all three military classes, REACH, all lane modifiers, ADD/MULTIPLY ordering, Keystone restrictions, PASS measurement, and late-BUILD measurement. It is not the final launch roster.

Authority order is: owner-approved V1 rules in `EPOCH_Core_Gameplay_Spec_v1.md`; `EPOCH-master-reference.md`; `hooked-player-playbook.md` as supporting research only; then entries explicitly labelled `PROTOTYPE-TUNABLE`. No entry changes the random seed or shared offer sequence. Choice state affects legality only.

**Provenance correction (content 1.0.1-v1).** Every authored BUILD, TRAIN, PERK, and KEYSTONE entry—including its ID, name, roster slot, effect package, and balance values—is `PROTOTYPE-TUNABLE`. Authority attaches only to inherited rules, never to the invented entry. The JSON therefore carries a `ruleSources` array on every entry. BUILD entries cite BUILD resource/cost, resolving-Age tier, and lane scope; TRAIN entries cite TRAIN resource/cost, Age Power, and the counter triangle, plus REACH where applicable; regular perks cite ADVANCE resource/cost, effect ordering, and uniqueness; Keystones cite ADVANCE resource/cost, effect ordering, and the maximum-one rule. This corrects provenance only and changes no mechanics or Age-table number.

Costs are never authored as numeric card values: BUILD, TRAIN, and ADVANCE read the resolving Age's locked cost. BUILD tier and base yield also read the resolving Age. All effects use only `ADD` or `MULTIPLY`, carry explicit priorities, and resolve by the Core Spec total order. Commander effects are absent.

Each row contains every required authoring field. The JSON companion is the executable source of truth; this table is its human-readable mirror. “Age” is inclusive. Effect notation is `operation magnitude targetStat [scope; trigger; priority; source]`.

## 3. Offer eligibility and shared-hand contract

All 48 entries are offer-eligible inside their Age bounds. Slots are independent weighted type draws; duplicate types are allowed and duplicate IDs are deterministically redrawn from that slot's indexed stream. The hand is never filtered by resources, perks, lane capacity, or choices. Illegal cards remain visible. PASS occurs only when a side has no legal card.

The effective weights are 70/20/10 on turns 1–3, 45/35/20 on 4–6, 35/40/25 on 7–12, 20/45/35 on 13–18, 20/50/30 on 19–20, and 0/60/40 on 21–24, ordered BUILD/TRAIN/ADVANCE.

### 4.2 Integrity and eligibility checks

- Unique IDs: all entry IDs and all effect IDs are globally unique.
- Reference integrity: every effect's `sourceId` equals its containing entry ID; every localization entry has both name and effect keys.
- Provenance integrity: every entry is `PROTOTYPE-TUNABLE`, has a non-empty `ruleSources` array, and cites only inherited rule identifiers; no authored identity is labelled as authoritative.
- Age eligibility: `1 <= minAge <= maxAge <= 4`; Keystones have `minAge=3`; each TRAIN is restricted to exactly one Age.
- Offer sufficiency: each Age has four TRAIN IDs, at least four ADVANCE IDs, and four BUILD IDs where BUILD weight is non-zero, so a three-ID hand can always resolve collisions.
- Effect order: operations are only ADD/MULTIPLY; every effect has an explicit priority; defaults are ADD 100 and MULTIPLY 200, with conversion debits explicitly at 90.
- One-line text: warning threshold is 48 characters. Current JSON validation reports any exceptions; concise labels are recommendations, not authoritative logic.
- Cost integrity: no content entry contains a numeric purchase cost.
- Seed integrity: no effect targets seed, RNG, offer, draw, or hand state.

### 4.5 Remaining balance assumptions (non-blocking)

- All income MULTIPLY magnitudes are integers, so this manifest does not require a new income-rounding decision.
- Recurring conversion debits are legal only when they cannot drive the authoritative resource below zero; simulation should measure how often that condition suppresses the conversion.
- +2 class Power, +1 lane Power, ×1.10 general Power, and ×1.20 Keystone Power are starting test values, not balance locks.
- Dual Ledger may dominate single-resource +1 perks; it intentionally provides a ceiling comparison.
- River Mill duplicates Growth Works mechanically except for player-facing emphasis; retain until RIVER pick-rate coverage is adequate.
- Garrison Post's +1 Power may make it outperform other BUILD definitions despite equal cost/yield; late-BUILD selection and win-rate deltas must be measured.
- Keystone ×2 structure yields and ×2 contested yields require simulation for runaway resource accumulation; resources remain uncapped by rule.
- The pool is deliberately small, so duplicate perk appearances and per-side illegality will be common enough to measure PASS frequency.
- Utility entries use `TEMPO` as their engine archetype and `UTILITY` as a manifest tag because the Core Spec has no UTILITY enum.
- No balance assumption changes deterministic resolution; tuning any magnitude requires a new `contentVersion` and pool hash.
